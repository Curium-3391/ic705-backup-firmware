  • No real hardware dumps or official Icom files are included: For copyright and privacy reasons, this repository contains zero official Icom firmware files and zero real radio dumps (no IC704, IC553, EEPROM, or WLAN dumps). Everything runs locally in your browser on the official .dat file you supply.
  • Japanese domestic version (JP J140) verified ONLY so far: Real-hardware lifecycle testing (G1–G7: backup, SHA-256 verification, auto-reboot, stock restoration, third-party restoration) has so far been performed only on a Japanese domestic IC-705 running official 705J140.dat (v1.40). EU/Global/US models (705E140.dat) have different ARM addresses and are not yet supported. Community verification and regional porting contributions are warmly welcome!
  • Zero non-volatile writes, stock bootloader untouched: The backup payload executes strictly read-only operations against all 5 chips (storage_write_operations = 0), leaves the 64 KiB stock bootstrap untouched, and only offers a download if both MD5 and SHA-256 match the hardware-verified build byte-for-byte.

What This Backup Firmware Does

Without opening the radio, desoldering chips, or attaching clip programmers, the generated 705RB3B5.dat reads all five non-volatile storage devices in the IC-705 onto your SD card (/IC-705/) with dual-pass SHA-256 readback verification:

    Safe Flashing & Operation Procedure

    1. Turn OFF Wi-Fi and Bluetooth on the IC-705 before starting.
    2. Copy only 705RB3B5.dat to /IC-705/ on your SD card (make sure no RB3_*.TRG file is present yet), and flash it via MENU → SET → SD Card → Firmware Update.
    3. After the radio reboots, remove 705RB3B5.dat from the SD card and place RB3_FULL_BACKUP.TRG (content ARMED\r\n) into /IC-705/.
    4. Enter Firmware Update once to trigger the full 5-chip read-only backup. Wait patiently until the radio automatically reboots via its watchdog.
    5. Do NOT add a new trigger. Enter Firmware Update one more time to export the post-restart receipt (RB5_COMPLETION.json and RB5_POST_RESTART.json), then cancel back out.
    6. Verify the backup on your PC, keep your EEPROM and WLAN dumps strictly private, delete any RB3_*.TRG files, and restore official 705J140.dat (or your preferred compatible firmware) via the stock SD Firmware Updater.

    One-Shot SD Trigger Kit (Generated Locally)

    Each trigger file is a 7-byte plain text file containing ARMED\r\n. Once executed on the radio, the firmware overwrites it to CONSUMED\r\n so it cannot re-run accidentally. Place only one armed trigger in /IC-705/ at a time, and never place an armed trigger while flashing the firmware itself.

    Known Observation: WLAN Flash Offset 0x8F040 (/sys/mode.cfg)

    During real-hardware validation comparing a standalone WLAN-only backup against a subsequent full 5-chip backup, we observed a 687-byte difference inside the TI CC3120 SimpleLink SFLASH filesystem. We document this transparently because it appears benign and does not indicate corruption:

    ItemFinding
    LocationWLAN Flash file /sys/mode.cfg (flash offset 0x8F040)
    Field offsetPayload offset 0x0C inside /sys/mode.cfg (80-byte payload)
    Observed change32-bit value 4 → 0 (only 1 payload byte changed: 0x04 → 0x00)
    Likely meaningStrong candidate: CC3120 NetApp service enable bitmap with mDNS bit 0x04 cleared (not yet formally proven 1:1 via live API correlation)
    Action required?None. Do NOT attempt to force this byte back to 0x04.

    Evidence & attribution: Out of 687 differing bytes between runs, 686 bytes are SimpleLink SFLASH metadata headers, counters, and mirrored backup records; only 1 payload byte (0x8F040) changed, and both captures independently passed dual-pass hardware SHA-256 verification. Static analysis of stock ARM firmware shows Icom's own WLAN stop/init routines call sl_NetAppStop(4) and sl_NetAppStart(...), with physical flash writes performed by the CC3120 network processor filesystem — the backup firmware performs zero flash write commands (storage_write_operations = 0). Without a real-time temporal trace, we cannot confirm whether the CC3120 persisted that state during boot, Wi-Fi stop, mode switching, or before bus acquisition. There is no evidence it causes any shutdown issue, and B4/B5 never modify this location.
